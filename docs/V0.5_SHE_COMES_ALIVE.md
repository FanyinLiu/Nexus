# v0.5.0 — She Comes Alive

> Decided 2026-10-30 by 音梵 after a team discussion. Status: planned.
> Theme: make the companion feel more and more like a person. Every feature
> below must stay in character: what she says and how she says it follows the
> active persona (she may act cute or play aloof if the character does).

v0.5.0 is one major release. It replaces the earlier v0.5 plan (Kokoro TTS +
Minecraft companion). The gaming companion stays off the roadmap until a
separate decision.

## Ground rules for every v0.5 feature

- **Persona first.** Any new line she speaks (reminders, jokes, anniversaries,
  call-mode fillers) is generated or selected through the persona layer, never
  a fixed system string in her mouth. A persona-consistency test covers each
  new speaking surface.
- **Off switch for everything.** Each feature has its own toggle in Settings,
  plain-language copy, and no developer jargon. Turning a feature off stops it
  immediately and does not require a restart.
- **Privacy fails closed.** New signals are coarse, local, and opt-in unless
  stated otherwise. Nothing new reads window contents, keystrokes, screen
  pixels, or stores raw audio or images. A refused or unavailable signal is
  never read and never retried silently.
- **No guilt, no pressure.** She never blames the user for being away, never
  locks features behind attention, and never escalates nagging.
- **Five locales.** All user-facing strings ship in en, ja (polite form), ko,
  zh-CN, zh-TW in the same PR.
- **Crisis and safety instructions are unchanged** by any v0.5 work.
- **Budgets.** Measured on an M4 Mac mini, 16 GB. Idle CPU added by v0.5
  features stays under 1% on average; no new always-on model is loaded unless
  its feature is enabled.

## Delivery order

Work ships in four milestones, each through normal PRs with CI green. Betas
are cut after A and after C.

| Milestone | Contents | Why this order |
| --- | --- | --- |
| A. Voice and call mode | 1 | Biggest "alive" jump; local Qwen3-TTS (#194) already merged |
| B. Relationship core | 2, 3, 6, 7 | Shared data model (stage, jokes, milestones, memory sources) |

## 1. Call mode

Hands-free talking, like a phone call.

**What the user sees.** A "Call" button on the pet and in chat. During a call
a clear in-call indicator stays visible (pet badge plus tray/menu-bar state)
with one-click hang-up. Text chat keeps working; the transcript of the call
appears in chat history.

**Pieces (voice audit tasks):**

- T6 — per-sentence emotion: each sentence carries its own speaking style from
  inline cues, then sentence heuristics, then the emotion snapshot, coloured
  by the persona. (In progress.)
- T2 — first sentence speaks early: start synthesis as soon as the first
  sentence is complete instead of waiting for the full reply.
- T7 — smarter end-of-turn: combine silence length with whether the user's
  sentence sounds finished, so she doesn't cut in mid-thought.
- T8 — backchannel: short "mm", "right", "and then?" while the user talks
  longer, in the persona's voice, rate-limited, never over the user.
- T3 — barge-in: when the user speaks she stops within the budget below, and
  only the part she actually said is kept in history, so she never "remembers"
  sentences the user never heard.

**Acceptance (M4 16 GB, local Qwen3-TTS, measured and written into the PR):**

- Time from end of user speech to first audio: p50 ≤ 2.5 s, p90 ≤ 4 s.
  Measure first; if local Qwen3 cannot meet this, call mode ships with cloud
  voice as the default and local voice as an option, not as a headline.
- Barge-in stop: audio stops ≤ 300 ms after user speech is detected.
- False barge-in from her own voice through speakers (echo): ≤ 1 per 10
  minutes in a scripted test with laptop speakers. Echo cancellation must be
  on; if it is unavailable the call UI asks for headphones.
- Backchannel: at most one per 8 s, never while she is speaking.
- History after barge-in contains only the spoken part (unit test plus one
  real-device check).

**Privacy.** Mic opens only after the user clicks Call. Raw audio is never
written to disk. Hang-up releases the mic immediately (verified by the OS mic
indicator turning off). The call stops if the window is locked or the system
sleeps.

## 2. The relationship grows

**Stages.** Stranger, acquaintance, friend, close. Progress comes from days
spent together and meaningful conversations, with a slow, capped rate per day
so it cannot be farmed.

**What changes per stage.** How she addresses the user, how much she teases or
acts cute, how often she speaks first, and which topics she brings up. Exact
behaviour per stage is defined per persona (a cool character warms up
differently from a sweet one).

**Rules.**
- Stages never go down.
- After a long absence she may sulk a little in tone only: no guilt-tripping,
  no locked features, no repeated mentions.
- The user can see the current stage in the memory/relationship page, turn
  the system off (she stays at the current tone), or reset it. Clearing all
  memory also resets the stage.

**Acceptance.** Stage transitions are deterministic in tests; a scripted
absence of 7 days produces at most one sulky line; the off switch freezes
behaviour; reset returns to stranger.

## 3. Inside jokes

She remembers nicknames, catchphrases, recurring gripes and running jokes from
conversation and brings them back.

**Rules.** Callbacks are rate-limited (at most one per conversation day by
default, more often at higher stages). The user can say "don't bring that up
again" in chat, which retires that joke permanently; retired jokes are listed
in the memory book and can be restored. Jokes are memory entries with a type
tag, so they follow the same edit/delete/"don't remember" rules.

**Acceptance.** Retired joke never reappears across 50 generated replies in a
test; rate limit holds; jokes are deleted with memory clear.

## 4. Her own day

She has a rough daily rhythm of her own: sleepy and quieter late at night,
slow to wake in the morning, a little more energetic in the afternoon. When
idle she reads, naps or hums instead of standing still.

**Rules.** Rhythm follows the user's local time and the persona. It only
changes tone and idle animations; she is never unavailable or refuses to help
because she is "asleep". Idle activities use existing Live2D motions first;
new motions only where the model supports them.

**Acceptance.** Idle activity rotation has no repeat within 3 cycles; no
extra CPU beyond the budget; turning it off returns the v0.4 idle behaviour.

## 5. Through the day with you

She learns roughly when the user is usually around or busy, stays quiet during
focus, and nudges gently for water, rest and sleep. The day after a late night
she may mention it once.

**Rules.**
- Uses existing v0.4 presence signals only (active/idle, rough intervals).
- Quiet hours (default 23:00–08:00 for nudges, editable) and a one-click
  "leave me alone today" that silences all proactive speech until next
  morning.
- Each reminder type has its own toggle and a minimum interval (water ≥ 90
  min, rest ≥ 60 min of continuous activity, sleep at most once per night).
- If the user ignores a nudge, the next one is spaced further out, never
  closer.

**Acceptance.** Scripted day simulation: no nudge in quiet hours, no nudge
while "leave me alone" is on, back-off after ignored nudges.

## 6. Anniversaries and a small album

Milestones such as the first day, day 100, day 365, the first late-night talk,
and the first call. On the day she brings it up once, in character.

**Album.** An "Our memories" page listing milestones with date and a short
line, browsable, editable and deletable. No photos in v0.5 (camera images are
never stored, see 10).

**Acceptance.** Milestones fire once; deleting one prevents it from being
mentioned; timezone change does not double-fire.

## 7. Memory book completion

The memory book already supports edit, pin and delete. v0.5 adds:

- **"Don't remember this."** Marks a memory as forbidden. The entry is
  deleted and a hashed guard prevents the same fact from being re-learned
  from later chats. Required tests: the fact is not re-extracted from three
  paraphrased mentions; the guard survives restart; memory clear also clears
  guards.
- **Where it came from.** Each memory shows which conversation and date it
  was learned from, with a link to jump there if that chat still exists.

## 8. She lives on the desktop

She can sit on the top edge of the active window, sway when it is dragged,
drop down or peek from the Dock when it closes.

**Rules.** Reads window position and size only, never titles or contents.
macOS first (Windows and Linux later). Off by default the first time; the
user turns it on from the pet menu. Never covers window controls; jumps off
in fullscreen apps and during screen sharing.

**Acceptance.** Position updates ≤ 100 ms behind window moves; no added CPU
beyond the budget when windows are still; permission refusal falls back to
normal floating.

## 9. The moment together

With consent, she knows the title of the song playing and the focus timer
state, so she can react to the third replay of a song or stay quiet while the
user focuses.

**Rules.** Coarse signals only: song title and artist, not lyrics or audio;
timer running/paused/finished. Each source has its own toggle and is off by
default. Reactions are rate-limited (one music comment per hour max).

**Acceptance.** With the toggle off the source is never queried; reactions
respect focus mode.

## 10. She can see you (camera, opt-in)

Recognises a few expressions (smile, frown, sleepy, away) to react naturally.

**Rules.** Off by default, separate explicit opt-in with plain explanation.
Runs on device; only the expression label is used; no image or video frame is
stored or sent to any model. Camera indicator visible whenever on; turns off
when the app is hidden or the system locks. Needs its own privacy review
before implementation starts.

**Acceptance.** No frame leaves the process (test plus network check);
camera light off within 1 s of disabling.

## 11. Reach her from your phone

A chat bridge, Telegram first, that talks to the same companion with the same
memory.

**Rules.** Runs only while the desktop app is running (no cloud relay in
v0.5). Pairing requires a one-time code shown on the desktop. Phone messages
are tagged as such in memory sources. Needs its own design and privacy review
before implementation starts; if that review is not done in time, this item
moves to v0.5.x without blocking the release.

## Release gate

v0.5.0 ships when milestones A–C are complete and pass their acceptance
checks, D items that are not ready move to v0.5.x, the beta has run its normal
validation window, and the release notes describe every new signal and its
off switch in plain language.
