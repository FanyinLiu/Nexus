# v0.5 portrait generation execution checklist

This is the living implementation checklist for the one-image companion track.
The accepted input scope is a front to three-quarter, half-body illustration on
a plain or transparent background. Full-body characters, photographs, busy
backgrounds and a general-purpose work-agent surface are outside this slice.
The broader desktop-presence roadmap remains separate; this work does not
change the stable version, release entry, or avatar selected by the user.

## Acceptance checklist

| Slice | Acceptance | Evidence required |
| --- | --- | --- |
| Model consent and attribution | Expand the existing companion settings disclosure to inspect required download size, model source, licence and incomplete training-data provenance; no automatic download; explicit consent; progress, retry and refreshed installed state | Behavior tests and an isolated Electron UI run in five languages at desktop and narrow sizes |
| Draft user flow | Use the native image picker; cancel safely; explain rejection; prevent duplicate generation; describe saved hair/head/body layers as a draft, without activating or claiming an animated avatar | Electron success/error/cancel checks, settings preserved, mock transport and inference clearly identified |
| Actual cutout | Use the pinned ISNet model for opaque input, retain original transparency, reject invalid/missing runtime and malformed masks, terminate the worker after each job | Tensor and lifecycle tests plus a real WASM inference on a synthetic local image; this is not visual-quality acceptance |
| Frozen acceptance | Lock exactly 20 local image hashes and expected outcomes, including at least two accepted dark-skinned characters; verify the whole manifest before running any inference | A report using the pinned models and final pipeline; no report may claim quality passed without the actual frozen corpus |
| Static draft preview | Write a transparent same-size `preview.png` from the actual layer union; commit the internal manifest atomically and clean a failed new draft | Pixel/alpha tests, retry after a failed write, and the existing three-draft retention checks |
| Limited-motion preview | Show the bounded union PNG in the requesting panel; start static, offer explicit start/pause for whole-image breathing and two-dimensional sway; clear pixels on close | Real Electron checks for decode, motion, pause, reduced motion, hidden/inactive states and unchanged selected avatar |
| Static export | Explicitly save the current preview as a format-2 package with zero motion intensity, optional verbatim attribution and no inferred expression layers; preserve the current companion | Cancel/error/retry, no-overwrite and path-boundary tests, package reader round-trip, actual export/import and isolated restart |
| Animated export and activation | Define a supported rig and explicit activation behavior; preserve the original avatar until the user selects a completed result | A subsequent independently reviewed implementation and visual/runtime acceptance |

The frozen illustration corpus is not present in the checkout. Synthetic test
fixtures prove execution and error handling, not suitability for the intended
artwork. User images are never uploaded, and real user settings or credentials
are not used for testing.

## Next engineering slices

The preview-only limited-motion stage combines the layers into one texture and
applies a shared affine transform for subtle breathing and two-dimensional sway.
Keeping the layers together avoids inventing pixels behind hair or the head.
No blinking, lip sync, head yaw or independent hair physics is promised. Invalid
geometry, reduced-motion preferences, a hidden window or pause retain the static
preview. Previewing never changes the selected companion. A successful real
inference still requires human inspection: the current coarse masks can include
clothing in the hair layer, which is unsuitable for independent layer motion.

The explicit static export uses format version 2, no expression layers and
`motionIntensity: 0`. Format 2 alone is not a static guarantee: it disables
procedural blink/mouth/head-yaw geometry but still supports other mesh motion.
The zero intensity is required for a static package. Export only saves a ZIP;
it never installs or selects a companion. The existing separate import action
selects its imported companion, so it must remain an explicit user action.
Supplied attribution is preserved in the exported ZIP; the existing imported
model store does not copy this sidecar, so keep the source ZIP with its licence.

Private `draft.json` stays at version 1 and now carries optional `metadata`
version 1. It records the EXIF-oriented source and analysis dimensions from the
landmark stage, the independently decoded layer source and working dimensions,
and the exact 28 source/work points and per-axis scale used for layering. Pixel
coordinates use the top-left origin, x right and y down. `recorded` only means
finite, serializable geometry: scores are not calibrated probabilities, low
scores are retained, and out-of-raster indices are marked without clamping.
Missing/non-finite points or scores make the group `unavailable`; no confidence
or anchors are invented. Different stage source sizes are flagged, and equal
sizes do not prove that the path contained identical bytes across both reads.

`expectedModels` is a projection of catalog pins, not runtime attestation;
`runtimeModelIdentity: not_recorded` is intentional for both worker and injected
engines. Native source alpha records cutout as `not_used`. The three raster
layers remain a coarse partition; eye, mouth and neck layers are known missing,
neck/shoulder/waist/hair-root anchors remain unknown, hidden pixels are not
generated and `motionReady` stays false. The missing-layer list is diagnostic,
not an exhaustive v4 validation result. This metadata follows the existing
three-draft retention policy, never enters IPC or the static ZIP, and is not
required to export legacy drafts or drafts with unknown metadata subversions.

Animated export remains a later capability contract. Half-body anchors must be
validated visually before enabling mesh motion. Do not relax the v4 validator:
v4 requires authored eye, mouth and neck layers even at its standard tier. Keep
generated-preview transfer bounded and local to the requesting settings panel;
do not introduce arbitrary file reads or bypass creator-kit path validation.

The colour-based layerer compares each below-neck hair candidate with observed
torso colours after all hair expansions. This prevents a wider hair-colour
radius from reclaiming pixels with stronger clothing evidence, without changing
the existing thresholds. It does not solve equal-colour connected hair/clothes,
accessory semantics or hidden-pixel reconstruction. Quality sets must remain
independent of diagnostic images used to develop this rule.

## Verification boundaries

Run `npm run verify:pr` on the final local code, followed by the dedicated
Electron portrait-flow smoke. Run the release aggregate before proposing a PR.
Keep the exact passing, failing and skipped counts with the source fingerprint.
Mocked UI transport, real ONNX execution and frozen-image quality checks must be
reported separately. No new PR, push, merge, tag or release is implied by a
passing local gate.
